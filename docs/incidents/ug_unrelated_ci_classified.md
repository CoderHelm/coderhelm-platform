# ug. `ug_unrelated_ci_classified`

**What happened:** A small web fix's preview check failed on an end-to-end test of another page. CoderHelm's CI fix round showed the failure wasn't the change's: the staging data the test reads changed three minutes before the test ran, staging (the base branch's build) showed the same mismatch, and the change touched nothing on that page. The round changed no code, which was right. The run still ended "failed", the pull request stayed a draft, and the run said CoderHelm "made 1 fix attempt(s) without getting it green" while its record counted two rounds. The check runs only on pull requests, so its comparison with the base branch's head never ran, and the round's proof counted for nothing. Earlier in the same run, a review fix round ran out of time three steps in a row: each step read the same files again and edited a file the step before had put back on purpose, then put it back again.

**The guarantee:** A round that changes no code and shows, with evidence, that the failure isn't the change's is classified. The failed jobs run again once. If they pass, the run carries on like any green run. If they fail again, the run is completed with the failure as its own outcome (`unrelated_test`): the pull request and the run name the failing test and the proof, the test is handed to its own flaky-test fix (one per test), and the pull request goes ready. A check that never runs on the base branch finds its base on the base branch's recent commits, then in the failing test's own runs on the base branch. A red ending counts CI fix rounds and pushed fixes as the run's record has them, and never calls a round that changed no code an attempt. A step that continues a round is told what the steps before it wrote and put back, so it goes on from there.
