# mz. `mz_merged_result_passes_before_merge`

**What happened:** Two pull requests each passed CI and merged one after the other. The first added a required field to a shared struct; the second's new code built that struct without it. Each head was green against the base it was tested on, but the base branch's rules didn't ask for a branch to be current before merging (and an admin merge skips that rule anyway), so the second merged on checks that never saw the first. Together the base branch didn't compile.

**The guarantee:** CoderHelm never merges a head its base has moved past. Right before every merge it makes (`GitHubClient::merge_pull_request`, the one call every merge goes through), it compares the head with the base branch's tip. When the base has commits the head lacks ("behind" or "diverged"), nothing is merged: the auto-merge gate says why on the pull request, merges the base into the branch with the same base merge it uses for a conflict, and goes on on that new commit, where CI runs on the merged result and the gate merges only once it is green. This holds on every repository CoderHelm merges in, whatever the branch's rules say, and a comparison it can't read is an error that is retried, never a merge.
