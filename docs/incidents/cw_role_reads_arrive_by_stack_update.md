# cw. `cw_role_reads_arrive_by_stack_update`

**What happened:** AWS WAF alarm runs needed WAF, Athena and Glue reads on the WAF logs. They were first added to the CloudShell setup script (`coderhelm-read-waf`), with a one-line update shown as a setup item. Every team would have had to find and paste a script for each new read. The line patched a role CloudFormation had made, and it gave the reads to the data-source role `CoderhelmReadOnly`, while alarm runs read through `CoderHelmLogReader`. A release can't add a read by itself: CoderHelm's own roles may not change IAM.

**The guarantee:** Every read is declared in the role stack's one versioned template (`infra/cfn/coderhelm-log-reader.yaml`, published with each release), as named groups a stack parameter switches on: `WafLogs` (with `WafLogResults` and `WafLogKey`), `DatabaseClusters` and `Warehouses`. A WAF alarm run on an old role reads what it may and records what it was refused and what it found: the log bucket's KMS key and the workgroup's results location. It asks nobody. The install's one item, **AWS role reads**, is this release's one-click update of that stack, with those values filled in, which an AWS admin of the account creates. The same item names a role that is older than the release, and data sources the old script made. Those sources move onto the stack's role only after it reads them end to end. The data-source script no longer writes any permission: it creates or updates the role stack.
