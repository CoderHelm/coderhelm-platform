# da. `da_finished_run_ships`

**What happened:** Two runs on one ticket finished every planned task, opened their draft pull requests, and were then stopped with "CoderHelm stopped this run and handed it to you: its tasks were done and it had continued 4 more times without finishing". Of the four continuations, two were steps that ran out of time inside fix rounds that were closing findings, one was a step the run asked for by design so the changed tests could run with and without the change, and one was the fix round that check started. A fixed count of continuations after the work stopped runs that were still making progress. The stop also stayed on the run, so when the pull request's preview check went red with a readable error, the CI fix round hit the stop on its first pass and the run ended failed instead of fixed.

**The guarantee:** There is no count of continuations after the work. Each continuation names what it is for: the checks not yet run and the items they left open (`run_guard::Target`). The run goes on while each continuation closes something, and a step the run asks for by design is never counted. Once continuing closes nothing, or nothing is left, the run ships the pull request with what is open listed, and the stop is taken back at once (`run_guard::lift_shipped_stop`), so a red check with its error or a comment starts the next round. Finished work is never handed back and never failed because of a stop; runs stopped the older way are taken back the same way when their CI goes red.
