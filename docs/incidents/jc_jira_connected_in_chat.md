# jc. `jc_jira_connected_in_chat`

**What happened:** A new user on a self-hosted install asked chat what was waiting on him. Chat answered that Jira wasn't connected to Coderhelm, while Settings, Integrations showed Atlassian connected and runs from Jira tickets worked. The install had linked its Jira site through CoderHelm before the Jira app had its ticket lookup, and copied the hosted links once. The app gained the lookup in a minor version, which Forge rolls out with no lifecycle event, so the app never registered the new link, and the install never copied again. Chat counted "no lookup link" as "not connected", a different test from the one the integrations page used.

**The guarantee:** One answer to "is Jira connected" for every reader: the app registered with its secret, or a plain Jira webhook. A missing ability is named as that ability ("Jira is connected, but the app hasn't registered its ticket lookup yet"), never as "not connected". The system puts it right by itself: the app registers again on the first event after any version change, CoderHelm asks the app to register again through its project-list link whenever a link the app always registers is missing, and a linked install copies the hosted settings again whenever the triggers the site registered on CoderHelm change. Until then, tickets are answered from what Coderhelm's runs know.

**Where it's enforced:** `common::jira_connection::{Connection, Gap, missing_registrations, registered, copy_is_stale}`; in the gateway, `chat_work_tickets::{Jira, load}`, `jira_heal::heal`, `hybrid_install::{jira_sync_plan, refresh_jira_copy}`, `hybrid_jira::linked_triggers`, and the integrations page; in the Jira app, `register.js` (`registerIfVersionChanged`, `registerAgainReply`).
