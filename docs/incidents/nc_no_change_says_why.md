# nc. `nc_no_change_says_why`

**What happened:** An alarm started a run on a ticket that already had CoderHelm's open pull request. The run said it would continue that pull request. Its plan found, with evidence, that the code already did what the alarm asked. The run then ended as `completed` with no pull request and no error, and its notes stopped at the plan. The reason was only in the worker's log. Nothing was said about the open pull request, and the alarm's channel heard nothing.

**The guarantee:** When a plan finds that no code change is needed, the run ends with its own status, `no_change`, which the run page shows as "No change needed". The plan's full reason, with what it checked, is the run's summary note and its `no_change` record. If the run was continuing an open pull request, the run decides about it in plain words, both on the run page and in the pull request's status comment. Either the pull request is still needed, so it stays open and the run says why, or it is no longer needed, so CoderHelm closes it with a note and keeps its branch. If an alert started the run, the run replies on the alert's channels with the reason in one paragraph. If a ticket started it, the ticket gets the reason.
