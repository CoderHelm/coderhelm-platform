# y. `y_skipped_checks_wait`

**What happened:** A failing-test fix opened its pull request as a draft; CI passed and CoderHelm's review approved, and the ready check kept the draft until the checks that test the fix were green on its head. In that repository the preview and staging deploys and the end-to-end tests run only on a pull request that isn't a draft, so on the draft every one was skipped: draft, so skipped, so still a draft. A rerun replays the same draft event (and the app had no Actions write), so CoderHelm waited, deciding again and again for hours before giving up. Each recheck was decided twice, seconds apart: the run's own decision and the one its review verdict asked for each scheduled their own next recheck, so two chains ran side by side and spent the wait's budget twice as fast.

**The guarantee:** Why a check was skipped is read from its workflow file (draft conditions, a trigger only on `ready_for_review`, the labels its conditions ask for) and kept per repository. A draft never waits on checks that skip drafts: when the proof the decision waits on (a failing-test fix's checks, an end-to-end fix's repeat runs) skips drafts, the pull request is marked ready so it runs, the description says it is still being proven, and the result decides: ready once it passes, a hold with the reason when it fails. A check skipped for a label CoderHelm may not add (deploy, staging and production labels never are) or for a reason the workflow doesn't show is a hold with one plain action, never a wait. Every wait is bounded: unchanged on the same head for two hours, it is a hold that names what didn't happen. One recheck is pending per pull request, claimed with one conditional write.
