# aq. `aq_comment_during_run`

**What happened:** A run asked three questions on its ticket, proposed defaults and kept building. A person answered on the ticket twenty minutes later; the gateway logged that a run was in progress and dropped the comment. Nothing acknowledged it, the run never saw it, and its notes kept saying it went on without the answers. Comments written before any run existed were dropped too, and nothing read them when the run started.

**The guarantee:** A person who writes on a ticket CoderHelm is working on gets an acknowledgement, and what they wrote is acted on. The comment is kept once per comment id and acknowledged once (a reaction on GitHub, one short reply in Jira; never for CoderHelm's own comments or other bots). The run reads its open comments together at its next step boundary: answers and instructions go into the plan while it is being made; once the plan is final they become one round on the pull request when the step ends, where the code changes in the place the plan put the choice, and the ticket is told; a comment that says to stop ends the run at once. A comment nobody read yet stays open for what comes next (the next step, the round on the finished run's pull request, the ticket started again, or the next run), and comments written before a run started are read at its first boundary.
