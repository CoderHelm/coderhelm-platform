# cx. `cx_role_reads_wait_then_finish`

**What happened:** An alert route sent an AWS WAF signature-drift alarm (a Count rule counting a crawler's requests that got past a Block rule) to the team's terraform repository. The account's role stack predated the WAF reads the role template has, so the alarm's evidence (sampled requests, the web ACL's logs) was refused. The planner then asked CloudWatch for the alarm's own metric, `AWS/WAFV2`, and CoderHelm refused it itself ("isn't a namespace Coderhelm reads") although the role allows `cloudwatch:GetMetricData` on every namespace. It read the counts through New Relic instead, in several lookups, yet the decision was labelled "Not checked against the data (no lookups were made)" because only data-source lookups were counted. The run ended `needs_outside_change` with "Needed from you: Nothing" and asked a person to run an Athena query: the only missing read was the install's setup item, so nothing was left for any person, and nothing would ever take the run up again once the role could read.

**The guarantee:** Any CloudWatch namespace may be read: the team's role is the boundary, the common namespaces (`AWS/WAFV2` with WebACL, Rule, Region and its request counts among them) are hints in the tool description, a CloudFront web ACL's WAF metrics are read in us-east-1, and a refusal from AWS comes back as the install's setup item "AWS role reads", never as a refusal of ours. A WAF rule's matches are read without Athena: `waf_sampled_requests` (WAF's sampled requests) and `waf_log_objects` (the log objects straight from the `aws-waf-logs-*` bucket, bounded, grouped in the process by JA4, user agent, accept language, path and cookie presence), and the alarm's own evidence reads the log objects before it tries Athena. Every lookup the planner makes counts, so "no lookups were made" appears only when none were. A run whose plan changes no code ends `needs_outside_change` only when a person has an item; with none, a run the role was refused reads waits (`awaiting_setup`), raises the one install item, re-checks the role every 15 minutes and then daily (and at once when another run reads again), and starts again from its ticket once the role reads, to read the data and open its pull request. Any other run with nothing for a person plans again.
