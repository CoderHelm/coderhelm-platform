# db. `db_test_runs_in_its_own_package`

**What happened:** A web change added a unit test in the web app and an end-to-end spec in the repository's end-to-end folder. The check that runs each changed test with and without the change chose its sandbox's install from the end-to-end job, because one of the files was that job's spec, and that job installs only its own folder. The unit test printed `sh: 1: vitest: not found` both ways. The check read that as "fails with the change in place" and "no changed test fails without the change", spent a fix round rewriting a test that had never run, and listed two findings that weren't true.

**The guarantee:** The sandbox's install is chosen only by the files the sandbox runs (an end-to-end spec runs against a preview, never there), and a recorded job is kept only when its folder covers every file (`TestEnv::misses`). A test whose runner isn't installed didn't run: it is recorded as not run because the install failed, never as a failure of the change and never as proof of it. A test that did run and fails with the change, passes without it, or proves nothing is a check the change didn't pass: it holds the draft (`proof::holds_blocked_on`), even with CI green, so the run can't be done with it open.
