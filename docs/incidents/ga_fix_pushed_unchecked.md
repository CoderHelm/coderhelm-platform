# ga. `ga_fix_pushed_unchecked`

**What happened:** A pull request that removed a duplicated filter chip changed a shared slug helper and added hundreds of lines of unit tests for a few dozen lines of code, with fixture ids `dock-a` and `dock-b` although the run had looked up the two real records. CI went red on a test outside the diff. Every CI fix round's sandbox said "2 of 2 checks passed": its test step was another package's `npm test` with `--passWithNoTests`, so no touched test ran, while the coder's own `vitest run` of the touched files exited 1 again and again. The fixes were pushed anyway. After several attempts the supervisor put a source file back to an older green head in a commit titled "Revert the change that broke CI" and left the tests that expected the reverted helper in place.

**The guarantee:** The sandbox runs the owning package's own scripts: its whole unit suite when a non-test file changed, only the touched test files when nothing but tests changed, and its type check and lint (`common::push_gate::package_steps`). A CI fix is pushed only when those ran on its last edit and passed; one the sandbox couldn't check is pushed with `Unverified:` and what ran (`push_checks::before_push`). A commit message that disagrees with its diff is rewritten from it (`round::land`). A commit that removes a definition a test still names is held until the test goes with it. A failing test gets two pushed fixes; then the rounds stop with the test and its error named, and nothing is rolled back. Invented fixture ids and three or more test cases that differ only in their values go back to the coder (`minimal_change`).
