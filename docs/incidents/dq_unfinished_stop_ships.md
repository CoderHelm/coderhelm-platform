# dq. `dq_unfinished_stop_ships`

**What happened:** A run on a large ticket finished part of its planned tasks, then spent several steps reading the same files and writing nothing, because the files it was told were missing already had their planned form. The guard ended it with "CoderHelm stopped this run and handed it to you: it continued N times without finishing another task". Another run did the same on a one-line documentation change: each step re-read the file, thought to the output limit and wrote nothing. The measuring and the cut replies were fixed on their own, and a stuck task now climbs the supervisor's ladder. But the guard's count of continuations without a finished task still ended the run one step after the ladder deferred the first stuck task, in words that hand the work to a person, and the stop stayed on the run, so the draft it shipped could not take a CI fix round.

**The guarantee:** A run whose planned tasks stop moving changes approach first: the ladder (one task, fresh context with edits in place, a re-split, the strongest model, then the task deferred) runs before the guard's count is spent. When the count is spent, the run ships what is done with the rest deferred, and says so. That stop is taken back once the work is on its pull request, so CI's errors and comments start the next round. A CoderHelm limit never hands unfinished work to a person.
