# mx. `mx_gate_keeps_the_branch_current`

**What happened:** A person approved someone's pull request and the auto-merge gate armed. Three seconds later the gate found the pull request conflicting with its base and stopped: on a person's pull request it never brought the base in (`updating:false`), it only told a person to resolve it. Twelve minutes later a person pushed the conflict resolution. CoderHelm reviewed only the pull request's own change since its approval and approved again, and the gate armed and stopped at once with "waiting on approvals". The person's approval was of the earlier commit, and the gate counted only approvals of the head, though GitHub itself still counted it. The gate waited on a review event that never came, said nothing more on the pull request or in the team's channel, and the person had to dismiss their approval and approve again for it to move.

**The guarantee:** A pull request behind or conflicting with its base is CoderHelm's maintenance, on anyone's pull request: as soon as the gate is armed (before a person's approval lands where the rules dismiss approvals on push) it merges the base in through the same conflict resolution runs use, once per head, compares the pull request's own change before and after with the reviewer's comparison (`review_scope::same_own_change`), queues CoderHelm's review of the new head itself, labelled pull request or not (a push's review, so the earlier approval is carried with the review it rests on when the pull request's own change is the one approved), and arms itself on the new head, where the review, CI and the keys are read again. The gate never waits on a review it caused. Only a conflict it can't resolve, or a fork it can't push to, is reported, once, with the files. The person key follows GitHub's own required-review rule (`reviewDecision`): an approval GitHub keeps counts, and with no rule an approval of an earlier commit counts when every commit since only brought the base in. When the gate waits on a person it names exactly what is missing (a dismissed approval and the commit that dismissed it, the branch's required count, who was asked) on the run page, in the pull request's one status comment and once in the team's channel, and it reads the pull request again every 15 minutes for a day, so a missed webhook can't strand it.
