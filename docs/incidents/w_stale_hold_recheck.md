# w. `w_stale_hold_recheck`

**What happened:** A finished run's pull request stayed a draft on an Open items line a wrong rule wrote ("the change makes the staging content its end-to-end tests read out of date"). The rule was fixed, but the line was text in the description and nothing checked it again, so the hold stayed until a person edited it. The same run spent several steps writing nothing while its plan check's count fell and came back each step, and the guard counted each return as progress.

**The guarantee:** Every blocked line names the version of the code that wrote it. A pull request held on a line other code wrote is checked again on its head in a fresh step of the run, once per run and code version, with the checks whose failure is a hold run again on an unchanged head; the Open items are then written from what they find. A line the running code wrote never starts another check. A fall in the plan check's count and its return count as progress only when the run's coder wrote code in between, and every plan check measures with the stacked base.
