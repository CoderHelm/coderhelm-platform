# df. `df_working_alternative_is_code`

**What happened:** A ticket said a charter card showed a broken image: the page used an older image address that returned an error, while the address the reporter expected was already stored in our database. The trace found the whole path: the charter's own record in the source system held the broken address, a second source record of the same kind (its fleet) held a working one, and our pipeline gave the charter's own image priority, so the broken one was stored and rendered. Many other charters carried addresses of the same kind. The run decided the fix was outside the code (edit the one source record), and a later run of the unchanged ticket stopped on that earlier verdict without planning again: "the ticket is unchanged since CoderHelm learned the fix is outside the code". A careful engineer makes the pipeline fall back to the working image, for every record.

**The guarantee:** A broken source value that our code chooses over a working one in its reach is a code fix. When a decision says `outside_code` and its own trace shows a layer holding a working value of the same kind as a wrong layer, and a layer that is code in one of our repositories, the plan check sends it back to fix that code (prefer, or fall back to, the working value, with a test), and the planner's guidance says so from the start (`fix_location::working_alternative`). `outside_code` stays right when no layer our code reads holds a working value. An earlier "outside the code" verdict is judged again under the same rule before it may stop a new plan on an unchanged ticket (`TicketHistory::guard`).
