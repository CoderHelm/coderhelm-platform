# sl. `sl_scope_decided_once`

**What happened:** A pull request fixed a duplicated filter chip. Its plan put the `/classes/<sport>` path pages out of scope "as an open product question", answered each question with "meanwhile", and still had a task to "switch any other caller". Three days later a round built the path pages; the tests and scope check took the code out but left its tests (that check exempts tests); the automatic revert put the tests back for code that was gone; a person deleted them by hand. The description said the path pages were out of scope while the diff changed them, and asked the team the questions the plan had answered. In the 53 runs audited, 19 of 38 recorded plans left product questions open and 8 branches had a file go in, out and back in.

**The guarantee:** Scope is decided once, from the ticket's acceptance criteria (`stop_judge::acceptance`) and the plan's `## Out of scope` section, when the plan is generated and before any code (`common::scope_ledger`, kept on the run). A plan with no such section, an open question, an item without a reason, an item a criterion asks for, a task that names an out-of-scope item or an open-ended task goes back to the planner. Every round's tests and scope check reads the diff, tests included, against the ledger; a planned-work round never builds an out-of-scope item; a scope change needs a `Scope change:` line that cites a criterion or a person's comment, and the ledger records who moved it in. The description renders one Out of scope line from the ledger, turns question sections into defaults, and drops any sentence the diff refutes.
