# gb. `gb_red_ci_stops_named`

**What happened:** A pull request's end-to-end check failed on "selecting a slip adds it to the cart while booking is open" with `Total$0`. After three fix attempts the supervisor rolled several of the pull request's files back to an older green head. The test failed the same way on the result: the booking vendor's portal had opened booking, so it was red on every branch. Other recent runs rolled their branch back the same way.

**The guarantee:** Red checks never roll a ticket run's branch back to an older head or take a planned task out; only a dependency run's newest set of bumps comes out (`resume::take_out_failing_bumps`). A failing test gets at most two pushed fixes (`common::push_gate::FixLedger`, kept on the run as `ci_test_fixes`). Then the rounds stop, nothing more is pushed, and the pull request and the run name the test and its error. When CI's job log can't be read, the fixer reproduces the failure with the owning package's own commands in the sandbox, and a sentence that blames the unreadable log is replaced.
