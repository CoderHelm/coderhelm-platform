# bg. `bg_coder_reaches_for_a_shell`

**What happened:** A fix round's agent log read "3 things didn't work". The coder called `bash` and was refused as an unknown tool ("Nothing says what bash does ... Carry on without it"), so the step was lost and nothing named the tool that did the job. Then two `edit_file` calls in a row failed with "`edits` was a string that isn't a JSON array": the array came as a string with raw line breaks inside its strings, which strict JSON refuses; the third try went through.

**The guarantee:** The coder has a `bash` tool (`common::coder_shell`): reads run as the file tools at once, the repository's own commands run in the sandbox on the committed branch under the agent permissions (exit code, time, the end of the output, a time limit, a few per step), and writes, git on the branch or the remote, network and secrets are refused with the tool to use instead. A call to another agent's well known tool name (`str_replace_based_edit_tool`, `Edit`, `Grep`, `view`, `ls`) runs as the CoderHelm tool that does the same job (`common::tool_aliases`), and where none is offered the refusal names the alternative. `edit_file` reads its edits from an array, a string holding one (raw line breaks, a fence, text after it, encoded twice), a single object or other tools' key names, and says exactly what was wrong only when nothing can be read.
