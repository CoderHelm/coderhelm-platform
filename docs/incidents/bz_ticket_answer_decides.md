# bz. `bz_ticket_answer_decides`

**What happened:** A run asked on its ticket for a page's heading and intro copy, with a proposed default. The product owner answered on the ticket to skip both and use the title. That run applied the answer as a round on its own pull request. Later a new run on the same ticket opened a new pull request: the comment was already marked handled, so the new run never read it, built the intro anyway and listed it under "Decisions pending product input".

**The guarantee:** Every answer and instruction people wrote on the ticket is a decision for every run on it, whichever run handled it. It is merged into the run's answers before triage and planning, read again at each boundary, and given to every coder round and every feedback and resume round. Wherever a description is written, an item the answers settle is taken out of the pending lists and listed under "Decided on the ticket", and an answer that goes against an acceptance criterion gets one line saying so. The decisions are kept per installation, so one team's never reach another's description.
