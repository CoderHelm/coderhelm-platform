# vt. `vt_stable_promotes_on_evidence`

**What happened:** Stable promotion was a clock. A beta became stable once it had been out for a day with no open `release-blocker` issue naming it, and nothing ever filed such an issue. One beta became stable without being installed on any live install. Another became stable while Chat was broken on it, a few hours after the fix had shipped in a newer beta that was simply too young. A later promotion failed with HTTP 403 when it created the stable tag: the tag points at an older commit, `main` had changed a workflow file since, and GitHub refuses the workflow token creating a ref that counts as changing workflows. And the schedule that started promotion ran hours late every day.

**The guarantee:** A beta becomes stable only on evidence from a live install: its post-update watch ended healthy, at least one run finished on it, and at least one Chat answer finished on it where that install uses Chat. A beta that an install rolled back, or that an open `release-blocker` issue names, is never promoted; the newest beta with evidence is, and its release notes say what the evidence was. Reports that can't be read promote nothing. The evidence is counts only, counted where the work finishes, and sent signed by installs whose admin turned the release report on. The stable tag's ref is created with the release-tag App's token when it is set up, and a refusal prints GitHub's answer with the permissions it wanted. Every published beta starts the promotion; the daily schedule is only a backstop, and running it twice changes nothing.
