# fa. `fa_stacked_pr_targets_its_base`

**What happened:** Two tickets asked for the same change (one for the work, a sibling to merge and deploy it), and two runs built it from the default branch separately. Their one-commit-per-file histories had several commits with the same patch id, so the first ticket's kept branch read as copying the sibling's open pull request. Every retry continued that same kept branch, which still held the same commits, and stopped before the pull request step each time: the rebase didn't apply, there were too many commits to replay, and the merge failed. A person had to step in.

**The guarantee:** A pull request a run reuses (its own open one, or a reopened one) moves onto the branch the run is stacked on, so its diff shows only this change and matches its description. A base that isn't another open pull request's branch is left alone. A branch that holds another open pull request's own commits (the same hashes) is already built on it: the run takes that branch as its base and doesn't rebuild or force push it again.
