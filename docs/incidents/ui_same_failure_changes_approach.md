# ui. `ui_same_failure_changes_approach`

**What happened:** CI fix rounds met the same failure again and repeated themselves. On one run four rounds read the same missing-content failure and each concluded "I made no code change". On another, three rounds read the same cloud-account limit. On a third, the error signature hashed only the report-upload tail of the log, so two unrelated runs had the same signature. The stall count rose, but nothing told the next round what the last one had concluded or that it had to do something else, and the fix budget ran out first.

**The guarantee:** The failure signature reads the failing report's own error line with the job logs. Each round's account is kept on the run. A round that meets the same failure as the round before it, with no progress, is told what that round concluded and must take another approach: a different hypothesis it checks with a command first, or the tolerant-code route when the failure names content. The stall halt still bounds the rounds after that.
