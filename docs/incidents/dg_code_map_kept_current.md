# dg. `dg_code_map_kept_current`

**What happened:** Every run rediscovered the repository. The planner listed the tree and read the README, the manifests and CI to learn the stack and the test commands, and then the coder did the same again before its first edit. The repository's agent file was written once at install, and again only when a top-level config file changed. Neither agent was given it, so each run paid for the same layout twice and nothing recorded how much.

**The guarantee:** Each repository keeps a code map on its agent file record (`common::code_map`). The map has sections for architecture, stack and versions, build and test commands, conventions, dependencies between packages, and one section per top-level area, each stamped with the commit it describes. Before the planner starts, the map is brought to the run's base (`passes::code_map::refresh`). If the commit or tree is unchanged, every section is reused. Otherwise only the sections that the comparison's paths touch are read again and rebuilt, in one model call. A section the reply left out keeps its older stamp, is marked as possibly out of date, and is rebuilt on the next run. The planner and the coder both get the map as context, and the build's tool calls before its first write are kept on the run with the map's commit (`exploration`).
