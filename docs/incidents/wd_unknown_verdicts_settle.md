# wd. `wd_unknown_verdicts_settle`

**What happened:** A team's Security fixes page showed most of its open advisories with the verdict "Unknown", and the high ones tiered P1 and shown overdue as if they were reachable. The daily model budget wasn't the limit: triage had read the whole backlog, most of it was answered "unknown", and those answers were kept for a week, so each later pass read only the few new packages. The code check had sent most of those packages to the model with lines that settle nothing: a type-only import, and lint or CLI scripts in `package.json` naming development dependencies. The tier then treated "unknown" like reachable for any runtime dependency with CVSS 7 or more, which set a seven day due date on advisories with almost no chance of exploitation.

**The guarantee:** A type-only import is neither an import nor a mention. A line that names only development dependencies is a development load, so a package that only development dependencies bring in is settled as not loaded, and one whose runtime ways in nothing imports is settled as not reachable, without the model. A verdict that isn't settled is never tiered as reachable: its score alone puts it one tier lower, and only the exploited list or EPSS raises it. Its tier and due date are marked provisional, and the overview counts it as not settled. The new check reads the code again once while a model answer is reused for the same lines, and the model reads the groups with the most exploitation risk first.
