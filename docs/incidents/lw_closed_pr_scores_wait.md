# lw. `lw_closed_pr_scores_wait`

**What happened:** A person closed four of CoderHelm's pull requests within ten seconds. Each close reached its run and queued its scoring, but the installation's GitHub budget was under the share kept for runs, so CoderHelm's own budget gate held every read ("Reward outcome failed: ... not sent, what is left of GitHub's hourly budget is kept for runs"). The message was consumed and nothing tried again; the lesson job lost its question the same way. The learning page read "Not learning: 4 closed pull request(s) were never scored" and told a person to check the GitHub App's pull request events, which had arrived.

**The guarantee:** A held or refused GitHub request is a wait for learning work, never a failure. The scoring and the lesson are sent again as themselves for after GitHub's reset, their waits counted and bounded, and scoring starts only when the budget has room for all of it. A sweep on the review-reminder tick finds every closed pull request with no score by the learning page's own rule and sends its scoring again: a few at a time, only when the budget allows, never while a try is in flight, and at most a bounded number of times, then it says why it stopped. Each signal is kept once, written whole or not at all, so scoring twice adds nothing. While CoderHelm retries, the page says so and when the next try is; it asks a person to check the GitHub App only for a close GitHub's event never brought.
