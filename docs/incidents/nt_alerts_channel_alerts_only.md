# nt. `nt_alerts_channel_alerts_only`

**What happened:** A team's alert channel, set up for production alarms, also got routine auto-merge status cards: a merge conflict that needed a person's call, and a wait on an approving review the branch's rules ask for. Every sender that wanted "the team's channel" opened the alert channel's settings item (`ALERT_NOTIFY`) itself: the merge gate, security and infrastructure cards, plugin reviews, turned-off webhook endpoints, knowledge sign-ins, and log findings whose own setting was never saved. The merge gate posted once per commit and wording, so each push could post again, and it posted a wait on a person's review, which is a pull request's normal state.

**The guarantee:** Every team-wide message has a kind: alert (a production alarm or incident and its follow-ups, a critical security finding), action (a person has to do something CoderHelm can't) or update (news). Its channels come from `common::notify::route` by that kind, and a test fails if any other file reads the alert channel's item. An alert channel saved before kinds existed takes alerts only; action and updates go to the team's updates channel (`UPDATES_NOTIFY`), or nowhere when there is none, and a team can tick more kinds for either channel in Settings, Alerts. The merge gate never posts a wait on people's reviews to a channel (the PR's status comment says it once), posts a conflict that needs a person only where action messages go, and posts it once per PR and reason (`await_merge::told_sk`). The log analyzer Lambda follows the same rule for new findings (`team_update_channels`).
