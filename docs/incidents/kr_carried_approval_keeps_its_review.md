# kr. `kr_carried_approval_keeps_its_review`

**What happened:** CoderHelm approved a pull request on a web app after a full review. A week later a person merged the base branch into it. CoderHelm saw that the PR's own change was the one it had approved, so it did not review again. Instead it posted a new approval on the new head whose whole body was one line: "Approved: the new commits only bring in the base branch; the PR's own change is the same as the approved `dab6dae`." plus the rating footer. Posting it rewrote CoderHelm's earlier reviews to "Outdated: see CoderHelm's latest review", and the tidy between reviews cuts a review of an older commit to one line, so the full review the approval rested on was gone from sight. The pull request's only visible approval had no review in it. A person said: "if this happens we have no review to check".

**The guarantee:** A carried approval stands on its own. Its body gives the verdict and why the earlier review still holds for the new head ("the PR's own change is unchanged since `<sha>`; the new commits only bring in `<base>`"), then that review as it was posted: what was checked, the criteria, the verification, the tests, the notes and findings. The content comes from the stored record of the approved commit's review (the posted body is now kept on every review record); the model is not run again. A carry of a carry keeps the one review and names the commit it was written for, with no nesting. While a carried approval is CoderHelm's latest review, the review it rests on is never rewritten, cut to one line or hidden, its comments stay in sight and its threads stay open; an approval posted the old one-line way is read the same way. A later real review, a merge or a close cuts both as before. With no stored review of the approved commit to carry, or only an old one-line carry with no review in it, the pull request is reviewed in full instead of approved with nothing in sight.

**Where it's enforced:** `worker::passes::review_pr` (`carried_review`, `carried_approval_body`, `carry_approval`, the `posted_body` on `store_review_record`, and the full review when nothing can be carried), `worker::passes::review_sweep::ReviewRecord::posted_body`, and `common::review_supersede` (`carried_from`, `live_carried_sha`, `kept_for_carry`, used by `plan` and `tidy`).
