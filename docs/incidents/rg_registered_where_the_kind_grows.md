# rg. `rg_registered_where_the_kind_grows`

**What happened:** Two new-feature runs drafted their pull requests and were blocked "new items aren't registered everywhere their siblings are" for places that register nothing. One run added a helper beside a set of content schemas, and the rule wanted it in the schema index, a navigation config and a one-off data migration that lists, once, the types it rewrote. The other added a UI component beside the site's other components, and the rule wanted it in the site's `package.json`, which only names packages as dependencies. People closed both drafts. The rule called a file a registry when it named most of a sample of eight siblings, and told places apart by folder names, so a backfill kept in another folder or a generated types file still counted, and a real index of migrations never did.

**The guarantee:** A registry is told from a file that merely names the items by what the file is, never by its folder or a list of names. It lists the kind: more than half of all its existing siblings, by path or as whole strings. It is part of the program: not prose, a test or its fixtures, a file the repository's generators write, or a file whose head says it is generated. And it grew with the kind: when it was written it named fewer of the siblings than it does now. A file that lists them but never grew is noted for a person, and one whose history can't be read isn't checked, so neither blocks. Only a checked registry blocks, and the coder is first told to add the entry itself.
