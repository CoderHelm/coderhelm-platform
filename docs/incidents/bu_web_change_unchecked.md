# bu. `bu_web_change_unchecked`

**What happened:** A run opened a pull request on a web app and called it ready with nothing looked at in a browser. The preview deploy and its end-to-end checks skip drafts and run on a label; the description was written while the pull request was a draft, so every deploy and end-to-end check read "skipped (its conditions left this PR out)" next to passing unit tests. It said "No screenshot: CoderHelm had no runnable preview", gave `npm test` as the way to check it, and the tests check passed on 0 of 6 changed test files failing without the change. A second pull request listed `npm test` in an unrelated folder under Open items and said the end-to-end log couldn't be read while the e2e workflow's comment named the failing test.

**The guarantee:** The preview and end-to-end jobs that cover the change, and the labels that start them, come from the workflow files; a draft is marked ready for checks that skip drafts and is ready only once they pass. A skipped check that covers the change is a gap CoderHelm closes, never evidence. The changed pages are captured at desktop and phone width once the preview is up. "How to check" and Open items name the CI job that covers the changed paths, or say none does. A failed end-to-end check is said from its own report, with whether the change caused it. Zero tests failing without the change is never a pass. The run page and the description say in one line what the pull request waits on.
