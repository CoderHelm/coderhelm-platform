# vn. `vn_each_repo_its_own_branch`

**What happened:** A run planned work in two repositories. Planning used most of its step, and both coders started with a minute or two left, so neither wrote anything. Each repository's pipeline still saved the run's own checkpoint as implemented, with its own branch, so the second repository's branch was the last one kept. The next step read that checkpoint as the run's, skipped the coder, and compared the second repository's branch in the run's repository, where it was never made. GitHub answered 404, and that one answer ended the run as failed with the HTTP error on the run page.

**The guarantee:** Each repository in a multi-repo run uses its own branch, made before anything compares it, and keeps its own checkpoint: the run's checkpoint only ever names a branch of the run's repository, and only after work is on it. A checkpoint naming a branch the run's repository doesn't have goes back to the plan, and the pass starts again without planning again. Each repository's coder starts with a step's full time, or in a fresh step. A compare of a branch not pushed yet is no diff, never an error. A run left failed this way is resumed by the self-heal sweep after the release and finishes with one pull request per repository, no second plan and no second follow-up.
