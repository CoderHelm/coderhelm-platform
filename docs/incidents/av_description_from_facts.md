# av. `av_description_from_facts`

**What happened:** An outside reviewer found a dependency security pull request's code sound and its description wrong in five places (a package row "not moved on the head" that the lockfile resolves at the patched version, an open item saying the lockfile was out of sync when a frozen install passes, a fixed advisory listed as not fixed, a wrong count of high advisories left, the package still listed as open). The title read `fix(deps): ...` where every merged pull request reads a ticket key and a summary, commits carried the prefix `KEY-1:` (a sample key CoderHelm had learned from its own description), a sentence said "contract unchanged" with nothing behind it, no major version jump said why it was safe, and CoderHelm's own review thread about the description stayed open. A second pull request, a three-file feature, carried a page about its outside steps that nobody could act on: a raw 403 with its JSON body twice, "needs access" beside "owner: CoderHelm", "after the pull request opens" long after it had opened, and found facts and a query already run listed as items with owners.

**The guarantee:** A description is a view of the facts recorded for its head. Every sentence a person or a model wrote is held against them on every rebuild of every kind of run, and one they do not bear out is rewritten from them or removed; what a model writes is checked before it is saved. What a reader sees first is rendered from the facts (the change, how to check it, the risk, what they have to do or that nothing is needed, anything out of the ordinary with its evidence) within a budget; everything else is collapsed. A step outside the code has one owner and one state, generated every build; a check CoderHelm can make is made and reported as a result; a raw error is said as a cause with what lifts it. Titles and commits follow the form detected in the repository with a real key or none. A lesson that holds a placeholder is refused when learned and removed when found. A rebuild resolves CoderHelm's own thread that said the description was behind. The quality eval (`description_eval`) keeps both pull requests as cases.
