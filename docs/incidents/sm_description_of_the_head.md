# sm. `sm_description_of_the_head`

**What happened:** A vendor-portal pull request of 8 files went through 16 commits, and its description piled up history: an "Earlier attempts" section, "Deferred: reverted 7 file(s)" and "Waiting on CI" after the work came back, a note that scroll assertions were "dropped from this pull request" while the diff still changed that page object, and notes longer than the change. Another pull request's description grew to about four times its diff and contradicted it in three places.

**The guarantee:** Every build of a description, on every push, holds the written text to the head (`description_facts::hold_scope`, `common::scope_ledger`): sections about earlier attempts, pushes and waits go (the revert and "CI is failing" lines stay for `ci_lines`, which drops them once untrue); a sentence saying a file was reverted, put back or dropped while the diff still changes it goes; open product questions become out-of-scope defaults; the written notes fit a length scaled to the changed lines of code (150 to 600 words), with the run page for the rest. The visible part stays Problem, Changes (with one Out of scope line), Risk and Verification, and `pr_body::defects` fails any body that asks an open product question.
