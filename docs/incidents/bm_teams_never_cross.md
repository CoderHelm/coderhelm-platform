# bm. `bm_teams_never_cross`

**What happened:** An audit of every event path found four keys that named a shared thing instead of the team: any team admin could point a Slack workspace at their own team and take another team's slash commands; the run page's GitHub check reads were cached by repository name, so a same-named repository was served another installation's cached checks; model-written replies were cached by Jira ticket key and comment id, which two Jira sites can share; and run events were keyed by run id with no team on the row.

**The guarantee:** Every inbound route resolves its team from something only that team holds (a signed installation, a per-team token or secret, a claim no other team can overwrite) and drops an event no team owns. A Slack workspace or Teams webhook is claimed by one team at a time (`common::plugins::flag::claim_chat`) and routes only while that team still names it. Every process-wide cache is keyed by the credential or team that read it, and a reply is reused only for the exact prompt it was written from. Every run event row names its team and reads keep only the asking team's rows (`common::run_events`). Source scans fail on a new inbound route, a new cache or a direct events table access that does not say how it stays in its team.
