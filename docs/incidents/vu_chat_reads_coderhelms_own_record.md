# vu. `vu_chat_reads_coderhelms_own_record`

**What happened:** A person asked Chat why auto-merge was held on a run. The run page said CoderHelm's own review still asked for changes and named the open finding, but Chat's run record carried only the title, the step, the error and the notes. Chat read the repository's settings instead, blamed GitHub's branch rules, and the pull request was merged by hand past the finding. The same week, "What needs my answer?" listed runs that had asked nothing as questions to answer (one had failed on a token limit), ranked runs with no recorded requester as "needs you now", and Chat answered from a wiki whose sync had been failing for most of a day without saying so. None of the failed tool calls or the answers stopped on the lookup budget showed in the logs.

**The guarantee:** One reader (`gateway::routes::run_facts`) builds what CoderHelm decided about a run, and both the run page and Chat's run record take it whole: the merge standing, the own review's open findings, what the run waits on, its draft hold and its unfinished round. A run page field that is neither a fact Chat shows nor named as one it leaves out fails the tests. A need is listed only with its evidence (the stored question, or the one action the run names); a run with neither goes under "Stopped without a question" with what its record says stopped it, and urgency follows who it waits on, with no requester ranked last. Every knowledge passage and the setup check carry the base's sync health (last good sync, a failing or retrying source and since when), the answer is told to say so first, and the knowledge search can name one base. Each failed tool call is logged with its tool and error kind, and "Chat answered" carries the turns, the forced-answer flag, the seconds and the intent.
