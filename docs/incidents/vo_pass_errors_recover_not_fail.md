# vo. `vo_pass_errors_recover_not_fail`

**What happened:** Any error a pass returned that the run had no special case for ended the run as failed, usually with the raw HTTP error as its reason. Some were passing (a 5xx in the middle of the coder's work), some were states CoderHelm could put right itself (a branch that wasn't there, a base branch someone deleted), and the run tried the same thing again in a fresh step without changing anything until its ceilings ran out.

**The guarantee:** Every pass error takes one recovery path before anything is marked failed. It is classified as transient (tried again after a backoff), a state CoderHelm repairs (repaired, then the same pass resumes from its checkpoint, with no second plan and no repeated ticket or pull request), or something only a person has. The same error again with no progress takes the next repair strategy, never the same one. Only a person's step stops a run, as "needs you" with what to do in plain words. An error nobody classified is tried once more and then stops as "needs you", never as failed. Runs left failed on an error CoderHelm now gets past are resumed by the self-heal sweep, on deploy and every 15 minutes, once per run per deploy.
