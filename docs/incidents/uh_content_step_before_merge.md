# uh. `uh_content_step_before_merge`

**What happened:** A feature put structured data on club pages from addresses in the CMS. Staging had none, so the change carried a migration to fill them, and its own end-to-end test failed by name until the migration ran ("... is incomplete in this dataset; run apps/studio/migrations/..."). The plan made running that migration CoderHelm's step and told the person "Needed from you: nothing", but the repository had no staging CMS write connection, which CoderHelm only found after the pull request opened. The code was right: it left the block out when the address was missing. So each CI fix round changed nothing, four rounds met the same failure, the run's fix budget ran out, and the run ended "failed". A second feature on the same install met the same shape with test fixtures that a migration adds.

**The guarantee:** A failing test that waits only on the change's own content step CoderHelm can't run ends the CI loop before any fix round is claimed. The pull request says what to run before merge, the run is completed with `ci_end` = `awaits_content`, and the pull request goes ready; auto-merge still won't merge over the red check. A build or page that fails on missing content is the code's to fix: the round is told to make it tolerant (leave the field out, log a warning), never to retry or edit content. The plan check makes a staging content step with no write connection a person's step before merge, decided at plan time. The new-feature checklist and the review flag app code that throws, asserts or exits when CMS content is missing.
