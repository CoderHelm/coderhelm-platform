# fd. `fd_red_ci_not_the_changes`

**What happened:** A pull request's preview end-to-end check, a job no workflow webhook reported, was recorded from GitHub's aggregate as an event that named nothing. For days every fix round read "Workflow 'unknown' failed (run_id: 0)": no check to compare against the base branch, no job log, nothing to re-run. On another pull request a preview deploy failed on a service limit of the cloud account; the fix rounds changed nothing, a re-run met the same limit, and the run took its own work out and failed.

**The guarantee:** An event written without a webhook carries the failing checks read from GitHub, the way a webhook writes them: the workflow's name, its run id, its conclusion and the failing jobs (`resume::synthetic_payloads`). No failure is described as a workflow named "unknown" with run id 0 (`resume::collect_ci_failure_info`). A failure whose log shows a limit of the cloud account (`resume::looks_account_limit`) is not the change's: no fix round or re-run is spent on it, nothing is taken out, and the pull request says so and names the repository's cleanup workflow when it has one.
