# de. `de_plan_check_gaps_once`

**What happened:** A ticket asked for a page block to work without JavaScript, with its structured data (`FAQPage`) in the server HTML. The plan's `## Out of scope` held one item decided with its default, and under it two indented lines recording what a lookup showed ("Looked up: ... `FAQPage` was not in the server HTML", "No lookup settles ..."). The plan check read each indented line as an item left out, so `FAQPage` became the mark of an out-of-scope item called "Looked up", and each of the five task lines naming it added the same gap. The run note and the decision's open gaps carried "A task names `FAQPage`, which `## Out of scope` leaves out" five times, telling the run to take the ticket's own ask out of its tasks. A second plan for the same ticket was told that an item about one script per page was asked for by the criterion "No layout shift when the page loads or when items toggle": the two shared only "when" (counted twice) and "page".

**The guarantee:** An out-of-scope section's items are its top-level bullets; an indented line under one, and any line recording a lookup, is that item's evidence and never an item (`common::scope_ledger`). Bold markers are no part of an item's name. What the ticket itself names (its title and body) is in scope: it is no mark of an out-of-scope item, and an item the ticket says in full moves in, both in the plan check and in the ledger kept on the run. A criterion asks for an item only on distinct words that tell items apart, never on common words or a word counted twice. Every plan-check gap is said once, in the run note and on the decision's open gaps (`scope_ledger::unique`, `FixDecision::add_gaps`), whichever check found it and on however many task lines.
