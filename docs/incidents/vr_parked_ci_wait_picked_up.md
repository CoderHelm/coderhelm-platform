# vr. `vr_parked_ci_wait_picked_up`

**What happened:** A run waited on its pull request's checks while an outside step waited on a workflow that never started. The CI wait reached its poll cap and handed off. The hand-off marked the run done, and the review that picks a finished run back up sent it to waiting on CI again. The check the capped wait had armed was still recorded as due, so the review's wait found a check "already due" and queued nothing. The run sat waiting on CI with no message left to wake it. The release that taught hand-offs to end the outside waits and reset the poll count came after, and its code runs only on a run's next resume, which nothing sent: the self-heal sweep read only failed runs, and the stuck-run sweep would only have closed the run a day later, skipping its review and outside steps.

**The guarantee:** A hand-off clears the due check it armed. A run waiting on CI with no check due and no write for an hour is parked, and the self-heal sweep (on each release and every 15 minutes) picks it back up with one resume: one conditional write claims it, sets its due check to now and starts its poll count again, so two sweeps never both send it and the resume's own chain goes on. A run is picked up at most three times; a live chain, a wait for GitHub's limit, or a run an invocation holds is never picked up.
